# B：算法与关键代码说明

更新：2026-11-15。用于团队技术材料，以下均按实际代码描述，不声称校准已提升效果。

## 评分协调器

core.grade_answer固定题目、规则和案例版本，先验证分档、分项与总分配置，再最多调用模型两次。每次输出校验分项完整性、规则编号、数值、精确引文及Unicode位置，总分用Decimal汇总。校验失败走修复；未解决风险走定向复核；两者共用预算。assessment_history保留已通过校验的候选，二次失败不会把第一次候选伪装为正式成绩。

checklist.grade_checked_answer增加细分检查项协议。source_units保留原文非空行与精确位置，模型只选行编号，程序恢复引文；旧逐字引文只接受精确匹配，不模糊修复虚构文本。模型给子项分，程序计算分项与总分。

operation_context按明确入队/出队/判空标题保守标记证据所在操作。标准方案不能只用入队片段支持出队搬移；正确替代方案按整体不变量评价。操作分析给出不完整/不确定时，相关整组满分会触发重新检查；这只能拦截部分内部矛盾，不是代码语义解析或形式化验证。

## 校准与检索

calibration.correction_draft把修改变成未批准草案，区分单份修正与通用规则建议。workflow.case_from_confirmed要求真实规则版本、完整教师逐项评分、精确证据以及单独的复用批准，保留审核来源。C负责真实身份、权限、持久化与发布。

select_cases只检索同题、同规则版本、单一案例集版本的批准案例；排除当前编号和去空白同文。中文二元字符及英文词片段集合以Jaccard相似度排序，忽略零相似度，默认取3条。这是词面检索，不是向量检索、微调或自学习。

## 风险和工具上限

规则、证据、替代解、文字代码冲突等风险进入复核。模型风险码不是可靠的正确性分类器；规则草案即使没有模型风险码也必须复核。无法调到服务返回FAILED，非法结构最终返回需复核且总分null，不能当0分。

MeteredProvider记录每次实际调用路径、输入摘要、延迟、服务报告token与安全错误码。每份作答不超过2次，实验另设全局预算。工具不做无限互聊或隐藏重试；C的显式任务重试须单独记录。

## 反馈与练习

feedback_and_practice仅在已确认结果与题目/版本匹配后，按教师确认的失分项输出本次观察，推荐审核题库中已有练习编号并排除已做题。没有题库或匹配项就不推荐；不虚构题号，不把本次失分解释为长期能力。

feedback_quality为推荐生成带摘要的人工适配审核任务；无审核时适配率未知，不能冒称学习效果。

## 评测与边界

experiments冻结同模型对照配置并逐条落盘，quality计算完整覆盖、共同有效子集、逐项误差、人工证据支持率及工时。引文存在不等于语义支持；教师修改后的最终成绩不等于模型自动评分成绩。标签未经逐项复核、开发样本已看过、服务端生成波动等限制须与指标一起报告。

当前只有开发试验，真实教师校准收益、封存测试、人工省时和练习学习效果尚未验证。没有冒称本轮使用CodeArts或完成华为云部署；这些须有后续真实记录。
