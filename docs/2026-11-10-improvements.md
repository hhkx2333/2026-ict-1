# B任务自主改进与真实实验记录

日期：2026-11-10。此文对应当前本地源码；未推送GitHub。评分规则仍为开发草案，全部建议强制教师复核。

## 已完成的改进

1. 模型不再计算中文字符坐标。最新协议把原文非空行编号，模型选择编号，程序还原精确引文和位置；相同行各有独立编号，保持原空白、缩进及Unicode位置。兼容旧逐字引文，但拒绝伪引文和模糊匹配。证据在原文中存在不代表语义上支持给分。
2. 把五点配分拆为8个检查项，程序计算分项和总分；检查缺项、重复、非法分档、无证据正分。漏写条件与已经正确写出的操作分别计分，避免重复扣分。开发澄清仍需教师认可。
3. 风险复核与结构修复共用最多2次请求；复核提供初次评分和理由。普通已明确失分与未解决的语义风险区分；不靠降低风险标记数量证明模型可靠。
4. 新增checklist接口及批处理入口，保留原有输出结构；规则配置提前验证。失败保留null或FAILED，不混同0分。密钥仅存本机忽略文件。

## 验证结果

48项离线测试通过；原有评分演示、校准合成演示和固定数据复算通过。覆盖Unicode/换行/缩进/重复行定位、非法引用、调用上限、修复、细分计分及命令行不覆盖既有输出等。离线测试只证明这些程序约束，不证明模型准确率。

真实服务均为DeepSeek，使用同一批原有10份公开匿名开发答案，没有发送新增答案。标签不进入评分调用；请求结束后才读取参考分。最新实验已获用户明确同意并实际完成，之前审批拦截已解除。

## 应该怎么继续改

优先处理评分口径，暂不继续扩大付费样本或对着参考总分硬调提示。把046/069/102/083交给老师，确认替代流程、搬移所在操作、含糊表达与代码笔误的处理，再形成真实逐项审核案例。具体问题见《待教师确认清单》。没有老师确认前，这些结果保持建议和人工复核，不变更为正式成绩。

A：组织上述逐项审核，另留未参与调试的数据。B：按教师决定发布新草案版本、接入真实审核案例并同批对照复测。C：按交接接口接入网页、任务处理、数据库和教师确认功能。模型费用可用不替代老师规则；目前没有完成华为服务接入或比赛全流程验收。

## 交付与复现

代码包只含源码、示例、测试和文档，排除.env、.git、缓存和work。运行档案单独存放。Python3.10+标准库即可运行：

```sh
python3 -m unittest discover -s tests -v
python3 -m examples.demo
python3 -m examples.calibration_demo
```

真实评分接口为backend.grading.grade_checked_answer；命令行使用--mode checklist；完整字段和配置见docs/b-handoff.md及docs/deepseek-local-setup.md。真实调用需用户自己的服务端密钥；新解压目录不会包含密钥或真实题库快照。
